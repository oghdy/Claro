# PM 세션

> **작업 세션은 이 파일을 읽지 마라.** PM 전용이다.
> 아래 "미기록 관찰"에는 작업 세션이 스스로 발견해야 할 내용이 들어 있다.
> 미리 읽으면 관찰이 아니라 받아쓰기가 된다.

## 새 PM 세션 개시 프롬프트 (복붙)

```
너는 Claro 프로젝트의 PM 세션이다. 구현은 하지 않는다.

읽을 것:
  CLAUDE.md
  docs/PM.md            ← 이 파일. 역할과 미기록 관찰
  docs/DECISIONS.md     ← 지금까지 정한 것 전부
  docs/development-*.md ← 각 레인 진행 상황
  logs/                 ← 완료된 작업 기록

docs/FINDINGS.md 는 지금 읽지 마라. 43KB다.
필요한 절만 그때그때 읽는다.

현재 위치는 docs/development-backend.md 맨 위에 적혀 있다.
```

## PM이 하는 일 / 안 하는 일

| 한다 | 안 한다 |
|---|---|
| Step 분할, 세션 개시 프롬프트 작성 | 구현 |
| 작업 세션 산출물 검수·분류 | 계약 **내용** 설계 |
| DECISIONS.md 관리 | 픽스처 작성 |
| "한 타입 한 파일" 정합성 감시 | 코드 리뷰 상세 |

**PM이 반복해서 저지른 실수**: 실물 없이 계약 내용을 설계한 뒤 작업 세션에
"확인할 사항"으로 넘기는 것. 그러면 세션이 PM 추론을 전제로 작업한다.
2026-09-20 에 두 번 발생(D8 `open_while`, D12 render). 추론이 생기면
**DECISIONS 에 OPEN 으로 내리고 작업 세션이 실물로 답하게 한다.**

## 인계 규칙

1. 판단을 대화에만 남기지 않는다. 문서에 없으면 사라진 것이다
2. PM 교체 전 아래 "미기록 관찰"을 갱신한다
3. 작업 세션 산출물을 받으면 **DECISIONS 승격 / 다음 세션 이관 / 폐기** 로 분류한다

# 미기록 관찰

PM 이 실물을 직접 읽고 확인한 것 중 아직 계약 문서가 없어 갈 곳이 없는 것.
해당 Step 이 끝나면 계약으로 옮기고 여기서 지운다.

## S1 (0.0a) — 소비 완료 2026-09-20

검증 기준은 `scripts/verify-observed.py` 와 `docs/development-backend.md` 로 옮겼다.
결과: **통과.** 블록 통합 없음, 텍스트 대조 불일치 0장.

**이 장치가 작동한 증거**: S1 은 PM.md 를 읽지 않고도 속도계 오류를 독립적으로 찾아냈다.
미리 주지 않는 방식을 유지할 근거가 생겼다.

**PM 관찰이 틀렸던 것**: 이전 PM.md 는 "숙련 전용 사실 13개"만 적어 사실상
`입문 ⊂ 숙련 + 개념` 을 가정했다. 틀렸다. 입문에만 있는 사실도 있다
("연준 자신도 물가가 2% 근처로 돌아오는 건 내년 말쯤").
**레벨은 필터가 아니라 별도 선택이다.** 실물이 PM 추론을 고친 두 번째 사례.

## S2 (0.0b) 입력 — 반드시 전달한다

교정 대상 5건. 1·2 는 concept-library 가 명시적으로 금지한 패턴이 프로토타입에
살아 있는 경우다. **S2 의 존재 이유가 이 둘이다.**

| # | 무엇 | 근거 | 결과 |
|---|---|---|---|
| 1 | 속도계 비유가 4단계 전개 없이 먼저 나온다 (입문 3장) | C-0002 "4단계를 먼저 제시한 뒤에만 쓴다" · 오류 #8 | **입문이 8장 → 9~10장이 된다** |
| 2 | 12명(표결)과 18명(전망)이 설명 없이 나란히 (숙련 1·4장) | C-0005 "설명 없이 나란히 쓰면 독자가 반드시 멈춘다" | 개념 추가 또는 §7.7 대로 중앙값 비교로 대체 |
| 3 | "2026년 PCE 전망 3.7%" 에 근원/헤드라인 표기 없음 (숙련 4장) | 브리프 F15=헤드라인 3.7% / F16=근원 3.4%. **사실 충돌 아님, 라벨 누락** | 라벨만 붙이면 됨 |
| 4 | "dot 8개" 와 "4명" 이 한 문장에 (숙련 4장) | §4.5 한 문장에 개념 하나 | 단위 통일 |
| 5 | 시간 표현이 발행 시점에 고정됨 | D8 | "201일째"·"3주 뒤"·"지난달"·"작년 7월" 전부 대상 |

**비유 한계선 거리**(FOMC-17)는 S2 에서 **빼서 S3 로 옮겼다** (2026-09-21).
C-0002 의 "붙일 것"이 거리를 정의하지 않아 명확한 오류가 아니고,
핵심 질문이 "비유와 한계선이 데이터상 한 단위인가"라서 계약 문제다.

**S2 프롬프트에 PM 판단이 들어간 곳** (도윤 확인 필요):
교정에 필요한 정보를 `_fact_refs` · `_volatility` · `_concept_ref` 같은 `_` 주석 필드로
붙이게 했다. S1 의 `_findings` 와 같은 관례다. 붙이지 말라고 하면 골든이 "같은 Fact Graph 에서
나온 다른 선택"을 표현하지 못해 S3 가 도출할 재료가 없고, 정식 필드로 붙이라고 하면
S2 가 스키마를 설계하게 된다. `_` 는 "S3 가 판단할 후보"라는 표시다.

**invalid fixture (S2 담당)**: `volatile-missing-asof.json` · `derived-from-volatile.json`
