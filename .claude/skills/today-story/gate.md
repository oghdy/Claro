# 게이트 — 폰 그림으로 하는 점검 (⑦)

`story:shots` 가 찍은 그림을 **장면 번호 차례로 전부** 읽는다 (01 표지 → … → 08 남음 · 짧은 이야기는 01 ~ 04). 글 파일이 아니라 **그림**으로 한다 — 도윤에게 "흐름"은 장면을 넘기는 박자까지다 (D104). 화면 · 그림 판단은 Fable.
법의 점검 열하나 (`docs/content/story-guide.md` 끝) 그대로다. 하루 기록 ⑦ 에 **예 / 아니오 + 어느 그림 · 어느 글**로 적는다. "예"만 열한 줄 적지 않는다 — 근거를 댄다.

| | 물음 | 어디서 보나 |
|---|---|---|
| 1 | 제목 위 한 줄만 보고 오늘 무슨 일인지 아나 · 큰 제목이 폰에서 두 줄 안인가 | `01-cover` · shots 의 "뉴스 한 줄 N 줄 · 큰 제목 N 줄" |
| 2 | 첫 화면 세 문장 안에 오늘의 일과 물음이 있나 · 표지 글이 오해를 단정하지 않나 | `01-cover` |
| 3 | 깨는 사실이 풀리는 장면 전에 어디에도 안 보이나 — 본문 · 인용 칸 · 꼬리표 · 단추 · **표지 그림** · 도구 카드 · 사슬의 멈춘 고리 | `01` ~ `05-aha-before` (코드 검사 R1 은 글 · 근거만 본다 — **그림과 뜻은 눈으로**) |
| 4 | 실마리에 누가 · 언제가 붙었나 · 인용을 자르지 않았나 ("…" 없음) | `03-event` |
| 5 | "뒤집어 보면" 상자를 빼고 읽어도 서나 · 뒤집기가 낳는 다음 물음을 받았나 | `06-aha-after*` |
| 6 | 단추의 물음을 다음 장면 첫 문장이 받나 | 장면마다 마지막 그림의 단추 → 다음 장면 첫 그림 |
| 7 | 제목의 물음 = 이야기가 푼 물음인가 · "그래서 무슨 일이었는데?"에 뉴스로 한 문장이 나오나 | `01-cover` ↔ `06` · `08-keep` |
| 8 | 같은 답을 여러 번 하지 않나 · 길이가 늘지 않았나 | `06` ~ `08` · story:check 의 "길이" 앞 → 뒤 |
| 9 | 숫자는 아라비아 숫자인가 (말의 셈 빼고) | 전부 · story:check W1 |
| 10 | **폰 화면에서 처음부터 끝까지 읽었나 · 쉽고 구체적이고 오버하지 않나** — 마지막 잣대 | 전부 — 한 화면에 글이 벽처럼 서는 곳 · 한 문장에 남의 말이 둘인 곳 · 추상적인 말만 있는 곳을 적는다 |
| 11 | 맞나 (구절 · 숫자 · 그리지 않을 것) | story:check OK (붙인 출력) |

## 화면에서 더 보는 것

- 가로 넘침 0 · 콘솔 오류 0 (shots 의 마지막 줄) · 글이 칸 밖으로 나가거나 겹친 곳
- 근거 시트 (`06-aha-after-sheet`) — 기관 이름 · 문서 이름 · 날짜 · 주소가 보이나 (출처를 밝히는 조건의 문서는 꼭 — D109)
- 이어짐 장면이 "남은 일들"인가 "다음 회차가 될 일들"인가 — `meta.json` 의 `unpromised` 와 맞나
- 맨 위 초록 띠 ("미리 보기 — 아직 올리지 않은 판")는 미리 보기에만 있다 — 실제 화면에는 없다

## 걸렸을 때

- **글** (1 ~ 10) → 쓰는 사람에게 그 그림 이름과 걸린 까닭을 그대로 (`writer-brief.md` 「메우기」) → ⑥ → ⑦ 다시. 이 세션이 문장을 고치지 않는다.
- **화면 틀 · kit · 그림** → 고치지 않는다. 하루 기록 "걸린 것"에 적고, 읽기를 막는 정도면 멈춤 2 에서 도윤에게 말한다.
- **견줘 읽기**: 고친 판이 나아졌다고 말하려면 앞 판의 그림 (다른 폴더에 찍어 둔다 — `story:shots <사건>/<code> <폴더>`)과 같은 장면을 나란히 본 뒤에 (D104 · D119 — "법에 맞나"와 "쉽게 읽히나"를 나눠 적고, 판정은 읽는 맛 쪽을 앞에).
