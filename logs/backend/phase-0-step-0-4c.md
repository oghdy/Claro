### 2 · 실제 Postgres

- **접속은 여전히 한 곳** — `apps/web/src/server/db.ts`. `DATABASE_URL` 이 있으면 postgres.js 로, 없고 `CLARO_PGLITE_DIR` 이 있으면 PGlite 로, 둘 다 없으면 열지 않는다 (배포된 서버가 접속 값 없이 임시 폴더에 쓰는 일이 없게).
  PGlite 를 남긴 까닭: 외부 DB 없이 도는 테스트와 `pnpm phone`. 갈래는 함수 하나 안의 `if` 하나다
- 마이그레이션 명령 — `pnpm --filter @claro/web migrate` (셸의 `DATABASE_URL`) · `deploy:migrate` (`.env.deploy`). 대상의 서버 이름 · 데이터베이스 이름과 적용된 개수만 낸다
- 테스트를 실제 Postgres 에서 — `CLARO_TEST_PG=postgres://localhost:5432 pnpm test`. `packages/db` 는 테스트 파일마다 `claro_test_<n>`, 화면은 `claro_test_web` · `claro_test_own`. 없으면 만들고, 안을 비우고, 마이그레이션 여섯을 적용한다. **이름이 `claro_test…` 가 아니면 아무것도 비우지 않는다**

### 4 · 배포 — 도윤과 같이

**PM 판정 (D35 끝 "0.4c 1 ~ 3")** — _open-1 탭 복제의 겹치는 seq: 그대로 둔다 · _open-3 API 전용 역할: **만든다** (아래) · `.env.deploy` · 스크롤을 뺀 것 · 빌드 때 싣기: 수용.

**API 전용 역할 `claro_api`** — `0006` 이 만든다 (로그인 없이). 넣기 · 읽기 권한과 그 역할만의 RLS 정책 15개. 비밀번호는 `deploy:role` 이 걸고 접속 값을 `apps/web/.env.vercel` 에 쓴다 — 화면 · 로그 · 저장소에 안 남는다.
- `packages/db` 테스트 +16 (85 → 101, PGlite · Postgres 둘 다): 그 역할로 시험 원장 전부가 들어간다 · 테이블마다 고치기 · 지우기 · 비우기 → 권한 없음 · 트리거 끄기 · RLS 끄기 · 칸 더하기 · 정책 더하기 · 테이블 지우기 → 주인이 아님 · 대응표에 쓰기 → 권한 없음
- 화면의 끝에서 끝까지 42개를 **서버가 그 역할로 붙은 채** 이 Mac 의 Postgres 에서 돌렸다 — 통과 (데이터베이스를 만들고 채우는 것만 주인으로)

**Supabase 에 올린 것 (2026-10-13)** — 전부 도윤의 `.env.deploy` 로, 이 컴퓨터에서. 접속 값은 출력하지 않았다

Supabase 에서 달랐던 것 (표의 Supabase 칸):
- **"automatic RLS" 이벤트 트리거는 마이그레이션과 부딪히지 않았다.** 이벤트 트리거가 7개 보인다. `0001` 이 RLS 를 한 번 더 켜는 것은 아무 일도 안 한다
- `anon` · `authenticated` 역할이 있다 — 권한 거두기가 실행됐고 남은 권한이 0 이다
- 직접 만든 역할(`claro_api`)이 풀러를 지나 붙는다 (사용자 이름은 `claro_api.<프로젝트>`)
- 오류의 칸 이름은 이 Mac 의 Postgres 와 같다 (같은 드라이버)

### 스스로 내린 판단

1. **기사를 캐시가 아니라 빌드에 실었다** (위). 잃는 것: 판을 바꾸려면 다시 빌드해야 한다 — 지금은 판이 하나고 배포가 곧 빌드다
2. **`/api/articles/…` 는 남겼다** — 데이터베이스의 판을 내려주는 길. 화면은 쓰지 않는다. "화면의 판 = 데이터베이스의 판" 테스트가 쓴다
3. **PGlite 를 지우지 않았다** (위). `DATABASE_URL` 이 이긴다. `dev` · `phone` 은 `DATABASE_URL` 을 비워 두고 켠다
4. **배포용 명령을 이름으로 갈랐다** — `seed` / `deploy:seed` 등. 접속 값 파일을 읽는 것은 `deploy:` 로 시작하는 것뿐이다
5. **`scroll` 을 손으로 치지 않았다** (_open-4) · 스크립트가 만든 입력(`isTrusted` 아님)도 치지 않는다
6. **`deploy:verify` 의 "덧붙이기만" 확인을 `truncate` 로 한다** — 줄이 0 이어도 문장 단위 트리거가 거부한다 (SUPABASE §4 의 `update` 는 줄이 없으면 아무것도 안 건드려 통과해 버린다). 거부되지 않으면 거래를 되돌린다
7. **0.4b 의 e2e 파일 이름을 바꿨다** — `record-killed.spec.ts` → `record-own-server.spec.ts` (제 서버를 켜는 테스트 셋이 한 파일에)

### 하지 않은 것

- 물음(probe) 화면 · 로그인 · 분석 화면. 화면 디자인 · 독자 글 · 골든
- 실제 독자(R-01 ~)를 올리는 것. Supabase 의 Data API · Auth · Storage 를 쓰는 코드
- Postgres.app 을 끄는 것 · `claro_test…` 밖의 데이터베이스를 건드리는 것
- 전용 데이터베이스 역할 (_open-3) · 탭 복제를 막는 것 (_open-1)

### 알고 가는 빈 곳

- (1 ~ 3 때) Vercel · Supabase · 실제 폰은 4 에서 처음 봤다 — 위 "4 · 배포". 실제 폰은 도윤의 아이폰 한 대 · 한 번 · 카카오톡 안의 브라우저다. **Safari 로는 본 적이 없다**
- "데이터베이스가 죽었다"는 닿지 않는 주소를 가리킨 것이다. 붙어 있던 접속이 도중에 끊기는 경우는 돌려 보지 않았다
- 로봇 테스트의 로봇은 이 Mac 의 Chrome 이다. 실제 메신저는 카카오톡 하나에만 붙여 봤다 (0줄). iMessage 등은 안 봤다
- 서버리스에서 접속이 얼마나 늘어나는지 재지 않았다 (인스턴스마다 3개까지 · 풀러 뒤)
- 배포된 화면의 서버 로그(거부한 줄)가 Vercel 에 얼마나 남는지 보지 않았다
- 배포된 주소에서 "데이터베이스가 죽었을 때"는 해 보지 않았다 (Supabase 를 멈춰야 한다). 이 Mac 에서 테스트로만 봤다
- `apps/web/.env.deploy` (주인의 접속 값) · `.env.vercel` (API 역할의 접속 값)은 도윤의 컴퓨터에만 있다. `deploy:role` 을 다시 돌리면 API 역할의 비밀번호가 바뀌어 Vercel 의 값을 다시 넣어야 한다
