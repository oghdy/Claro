**정답 표현은 모든 원형이 구조다.** `text`(정규 텍스트)는 구조에서 계산해 싣고, `text == linearize(block)` 을 발행 불변식으로 묶는다.

**D14 참고안과 다른 곳 — 이유**
1. **극성 목록을 따로 두지 않았다 → `contrast`.** rule_line 두 줄(✕ 금지하라 / ✓ 숨기지 마라), FTC 5장 경계선(해당 없음 / 이번 사안),
   tags(연방 / 주), votes(7월 / 9월)가 전부 **같은 물음에 대한 두 답**이고 모양도 같다(구분 라벨 + 내용).
   극성은 라벨 글자 자체이므로 D14 규칙 2 가 모양으로 보장된다. 극성을 enum 으로 따로 두면 라벨과 어긋날 수 있다(규칙 6).
   덤으로 근거 1건이던 극성이 근거 둘인 원형에 들어간다. 항목이 셋 이상인 극성 목록은 라벨 달린 `list` 로 쓸 수 있다
2. **강조 문단(callout) · 마무리(closing) → `prose` 의 `weight`.** 셋 다 서식 있는 글 문단이고 다른 건 무게뿐이다.
   closing 무게도 두 기사 모두에 있다. callout 무게만 근거 1건
3. **순서 목록 · 순서 없는 목록 → `list` 하나 + `ordered`.** 모양이 같고 순서가 뜻인지만 다르다
4. **`end_actions` 는 블록이 아니다.** "다 읽었어요" · "처음부터 다시 보기"는 프론트 UI, "헷갈리는 부분" 은 probe 진입(범위 밖)

근거 1건은 `sheet` · `scale` · (`prose` 의 `callout` 무게)다. `sheet` 는 넓히지 않았다 — 열 3개 이상 · 머리행 · 강조 행은 미확인.
"재사용률 0%"는 근거로 쓰지 않았다(D14).

### S3 가 정한 것 — 게이트에서 확인해 주길

`_open` 은 아니지만 결정문을 해석해서 정한 것들이다. 해석이 틀렸으면 여기서 뒤집으면 된다.

1. **`text` 를 구조와 함께 싣는다 (D14 규칙 6 해석).** 규칙 6 은 "둘 다 독립 저장하지 마라"다. 구조를 정답으로 두고 `text` 는
   계산해서 싣되 `text == linearize(block)` 을 발행 불변식으로 묶었다 — D8 `value_at_authoring` 과 같은 방식.
   싣지 않으면 D14 이유 1(모르는 타입이 왔을 때)이 성립하지 않는다. 프론트는 모르는 타입의 선형화를 모른다
2. **문단 `weight` 는 선형화에 넣지 않는다 (D14 규칙 2 의 "강조" 해석).** 규칙 2 는 극성 · 순서 · 강조가 글에 남아야 한다고 한다.
   구절 강조(`<b>`)와 항목 강조(`emphasized`)는 선형화에 `<b>` 로 남긴다. 문단 무게(부연 · 짚기 · 결론)는 명제를 더하지 않는
   리듬 정보로 보고 시각 규칙의 예외로 뒀다(§7.1-5). 규칙 3 의 판정 기준도 같게 잡았다 — "시각이 글에 없는 **명제**(수량 · 관계 · 판단)를 더하면 안 된다"
3. **출처 층에 `bridge` 를 넣었다.** 두 실물에 필드는 없지만, 골든에 bridge 문장이 실제로 있고(0.0b 게이트가 concept 표시를 뗀 문장)
   FINDINGS §4.1 이 Bridge 를 Evidence Layer 로 정의한다. 없으면 그 문장을 잘못된 층으로 달 수밖에 없다
4. **글은 span 배열, 경계는 데이터.** 골든 `_fact_refs` 의 `where` + 문장 분할 방식 대신 글 자체를 span 으로 쪼갰다.
   분할 규칙이 계약에 들어가지 않고, 같은 문장이 두 번 나와도 헷갈리지 않는다
5. **span 하나에 layer 하나, refs 는 그 층 것만.** 골든 17 span 이 `F-*` 와 `DC-*` 를 섞었다. Claim 의 근거 Fact 는 Claim 이 안다(0.2)
6. **open_question 은 레벨의 별도 배열, 길이 = 장수 − 1.** D17 의 "사이"를 위치로 표현. D15 QA① 이 길이 검사 하나가 된다
7. **인라인 서식은 `<b>` · `\n` 둘.** 골든은 headline 에 `\n`, 본문에 `<br>` 을 섞어 썼다
8. **D8 저작 데이터(공식 · as_of)는 패키지 밖.** 프론트가 그리는 데 필요 없다(D8 규칙 2 — 글이 곧 `value_at_authoring`)
9. **`title` 에서 브랜드를 뗐다.** "Claro — " 는 프론트가 붙인다

### 0.2 대기 표시의 모양 — S3 가 정함
