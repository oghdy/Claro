# local/chip-remote — 「칩 원격 사용을 막았다는데, 접속을 막은 걸까」 (짧은 이야기)

파이프라인 산출물이 아니다. 로컬 세션 (Sonnet 5.5)이 2026-11-17 에 손으로 쓴 판이다 (모델 API 0 · 파이프라인 명령 0). 편집자 (Opus) 의 빈 곳 목록 · 사람 게이트 (폰에서 읽기) 는 아직 안 거쳤다.
법: `docs/content/story-guide.md` · `logs/frontend/UX-8.md` ⑥ · `docs/contract/EPISODE.md` §13 (옛 꼴 — 장면 넷). 근거는 `store.documents.json` 의 BIS-PR-1116 · BIS-IFR 두 편뿐이다. 언론 기사의 글 · 숫자는 쓰지 않았다.

- `story.json` — 계약의 ShortStory (옛 꼴). 구절 20 은 문서 글에서 그대로 뗐다 (키: `pr` = 보도자료 · `ifr` = 규정 본문)
- `meta.json` — 깨는 구절 키 (`breakers`) · 깨는 말 (`ban`) · 목록에 적을 값 (`line` — day 는 올리는 세션이 적는다)
- 시리즈: 새 선반 「기술은 어디까지 나갈 수 있나」 (`tech-export`) 의 첫 이야기 (번호 · 시리즈 줄 없음 · 다음 화를 약속하지 않음 — `unpromised`)
- 숫자는 아라비아 숫자 (11월 16일 · 60일 · 90일). 말의 셈 ("두 군데" · "둘")은 한글

## 쓰기 전에

### 1. 세 줄
- **오늘 뉴스 한 줄**: 미국이 첨단 칩의 "원격 사용"을 막는 규정을 냈다 (11/16 · 미 상무부 산업안보국 임시 최종 규정)
- **끌고 갈 물음**: 칩 원격 사용을 막았다면, 해외 데이터센터에 접속하는 것 자체를 막은 걸까
- **다 읽고 한 문장**: "원격 접근"을 겨냥했어도 이 규정이 건 것은 접속 금지가 아니라, 그런 데이터센터로 칩에 붙은 허가다

### 2. 독자의 물음 차례 → 장면
1. "미국이 칩 원격 사용을 막았대 — 접속을 막은 거야?" → **표지** (물음 단추: 접속 자체를 막은 건가요?)
2. "그래서 발표가 뭐라고 했는데?" → **무슨 일인가** (첫 생각 → 문서의 말 → 누구 · 노림수 → 뒤집기 → 한국은 문서에 없음)
3. "그럼 구체적으로 뭐가 달라져?" → **문서가 말한 것** (허가가 붙은 길 둘 · 빠지는 것 하나)
4. "언제부터야?" → **남음** (날짜는 비어 있다 · 남는 한 줄)

### 3. 뒤집기 판정
- 센 말: 보도자료 · 규정 이름 · 보도자료 첫 문장이 "원격 접근 (remote access)"을 내건다. 규정 본문 전체에서 이 말은 세 번뿐이고 (이름 · "non-D:5 customer" 줄 · 추천 시스템 줄), **"접속을 금지하는 것이 아니다"를 말해 주는 곳은 0번** — 머리기사 말로 오해가 자연스럽다
- 깨는 글자: "restrictions which will apply for exports, reexports, or transfers (in-country) to overseas data centers" · "requiring a license for exports, reexports, or transfers (in-country) of advanced SI1 items … destined for use in data centers" · 보도자료 "existing controls on the physical shipment" · "License applications will be reviewed on a case-by-case basis."
- 세기: 중. **정직하게 — 문서도 효과는 원격 접속을 약하게 하는 것이라고 적는다** ("undermine those entities' ability to access … remotely, including through connected cloud computing"). 그래서 뒤집기를 "접속 쪽 목적 / 칩 쪽 제한"으로 좁혀 썼고 (문서가 말한 목적은 본문에서 먼저 보여 줬다), "중국 회사가 클라우드를 못 쓴다 / 쓴다"는 어느 쪽으로도 쓰지 않았다
- 앞의 말 "원격 접속을 막은 규정"은 독자의 짐작이지 문서가 부정한 말이 아니다 — 문서의 글자로 깨는 것은 "접속 금지"가 아니라 "접속 금지로 걸린 곳"이다

### 4. 깨는 구절의 키 (meta.json breakers)
`ifr02` (SUMMARY 첫째 문장) · `ifr03` (Background 첫 글머리 — 허가 · 수출 · 데이터센터) · `ifr04` (case-by-case) · `pr04` (보도자료 "physical shipment"). 풀이 전의 글 (표지 · 무슨 일 body · unknown · 단추)에는 이 키도 "내보내거나 넘기는" · "선적" · "쓰이는 칩" · "데이터센터 … 허가" 도 없다 (ban). 편집자 반영으로 무슨 일 body 에 "원래도 허가가 필요했다" (ifr17) 를 더해서 ban 에서 낱말 "허가" · license 는 뺐다 — 깨는 것은 "데이터센터에 쓰이는 칩에 붙는다"는 말이고 ifr17 은 그것을 말하지 않는다. 이 구절들은 `solve.entry.breaker` · `flip.note` 에만 달았다

### 5. 장면마다 독자가 여기까지 아는 것
| 장면 | 독자가 여기까지 아는 것 | 답이 먼저 보이나 |
|---|---|---|
| 표지 | 미 BIS 가 11/16 에 "첨단 반도체 원격 접근"을 다루는 규정을 냈다 · 문서는 AI 대신 SI | 아니오 — 제목은 물음 · 단추도 물음 (허가 · 칩 이동 없음) |
| 무슨 일인가 | + 첫 생각 → 문서는 새 제한이 "해외 데이터센터로 내보내거나 넘기는 일"에 붙는다 (여기서 풀린다) · D:5 · 마카오 회사 · 노림수는 원격 접속을 약하게 · 한국 말은 문서에 없다 | 화면이 이 장면 머리에 plain.title 을 놓는다 (옛 꼴의 틀 — 막힌 것) |
| 문서가 말한 것 | + 허가가 붙은 길 둘 (데이터센터 길의 고객 확인 · 다섯 나라 · 미국 본사 예외) · 추천 시스템은 빠진다 | 아니오 — 풀린 뒤 |
| 남음 | + 날짜 자리가 비어 있다 · 의견 60일 · 기존 데이터센터 90일 | 아니오 |

### 편집자 반영 (2026-11-17)
받음: 답의 축을 "칩에 붙은 허가"로 넓힘 (plain.title · flip.b · keep.line · 90일은 "계속 대 주려면") · 원래 있던 통제 (ifr17) 한 문장으로 body 둘째를 대체 · note 는 case-by-case 만 · 제목 "허가가 붙은 곳은" · 추천 시스템 예외를 데이터센터 길 안으로. 안 받음: dek 을 물음으로 끝내기 · plain.title 을 물음 꼴로 (제목이 이미 물음).
