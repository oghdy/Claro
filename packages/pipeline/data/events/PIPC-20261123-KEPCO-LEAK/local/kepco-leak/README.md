## 쓰기 전에

### 1. 세 줄
- **오늘 뉴스 한 줄**: 개인정보위가 11/23 한전 개인정보 유출사고 조사에 착수했다 (한전이 11/22 18시경 신고)
- **끌고 갈 물음**: 한전 개인정보가 유출됐다는데, 누구의 정보일까 (전기 쓰는 우리 집 정보가 다 나간 걸까)
- **다 읽고 한 문장**: 한전이 신고한 건 한전ON 고객정보와 전자조달시스템 이용자 정보 두 가지이고, 보도자료에 ‘모든 고객’이라는 말은 없다 (65만 · 87만 여명은 신고에 적힌 수 · 피해 규모는 이제 조사)

### 2. 독자의 물음 차례 → 장면
1. "한전 개인정보 유출 조사 들어갔대 — 누구 정보가 나간 거야?" → **표지** (단추: 한전은 뭐가 나갔다고 신고했대요?)
2. "전기 쓰는 사람 정보 다 아냐?" → **무슨 일인가** (첫 생각 → 깨는 문장 → 두 정보의 항목과 신고에 적힌 수 → 뒤집기 → 문서에 없는 것) (단추: 그럼 이제 어떻게 되는 거예요?)
3. "그럼 이제 어떻게 돼?" → **문서가 말한 것** (조사 항목 · 한전의 상담 창구 · 개인정보위의 감시 · 통지 받은 이용자의 주의 · 처분 예정) (단추: 그래서 한 줄로 하면 뭐예요?)
4. "그래서 뉴스를 어떻게 읽어?" → **남음** (남는 한 줄 · 주석의 날짜 — 해커 메일 11/19 · 다크웹 · 샘플 확인 11/20)

### 3. 뒤집기 판정
- 센 말: 뉴스 머리는 "한전 개인정보 유출"이다. 문서에 '모든 고객' · '전 고객' 같은 말은 **0번** — 문서가 적은 건 한전ON 고객정보 · 전자조달시스템 (SRM) 이용자 정보 둘과 각 항목 · 수다. 한전 = 전기 요금을 내는 우리 집이라 '다 나갔다'로 읽기가 자연스럽다
- 깨는 글자: "한전ON 고객정보1)와 전자조달시스템(SRM) 시스템 이용자 정보2)가 유출되었다고 … 신고"
- 세기: 중상 · 정직하게 — 문서는 '전기 고객은 안전하다'고도, '모든 고객이 아니다'고도 말하지 않는다. 그래서 상자도 깨는 글도 "‘모든 고객’이라는 말은 없고 적힌 건 둘"까지만 쓰고, 한전ON 이 무엇인지 · 전자조달시스템을 누가 쓰는지 · 전기 고객이 모두 몇 명인지 · 내 정보가 들었는지는 문서에 없다고 적었다 (지어내지 않음)
- 중립: 65만 · 87만은 "신고에 적힌 수"로만, 피해 규모는 개인정보위가 조사한다고 한 기관의 말로. '털렸다' · 조언 없음. 2차 피해 주의는 보도자료의 말 그대로 기관의 말로. 해커 메일 → 신고 사이의 날짜로 늦었다 · 빨랐다를 평하지 않음

### 4. 깨는 구절의 키 (meta.json breakers)
`pp03` (한전은 해커에 의해 … 신고하였다). `solve.entry.breaker` 와 뒤집기 상자 밑 글 (note · 풀이 장면)에만 달았다 — 화면 차례가 깨는 문장 → body → 상자라서 둘 다 풀이 뒤. 표지 · 첫 생각 · 단추 · 제목에는 이 키도 ban ("한전ON" · "전자조달" · "SRM") 도 없다. 표지 dek 는 구절 pp01 · pp02 (조사 착수 · 현장점검)만 기댄다. 항목 · 수 (pp04 · pp05)는 깨는 구절이 아니라 풀이 뒤의 body 에 있다 — 그래서 body 글은 이름을 되풀이하지 않고 "방금 말한 고객정보" · "이용자 정보"로 쓴다 (R1 은 body 를 풀이 앞으로 센다)
